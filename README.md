# Study Planner

Навчальний планувальник завдань. Лабораторна №9 продовжує лабораторну №8:
React State та Effects — Context API, useReducer, useEffect і Custom Hooks.

## Вимоги

- Node.js 22.22 або новіший.
- npm.
- Сучасний браузер із підтримкою localStorage та crypto.randomUUID.

```bash
npm install

```

Адреса сервера буде в терміналі.

```bash
npm run lint

```

## Можливості

- Створення завдань із назвою, описом, категорією та пріоритетом.
- Перевірка обов'язкової назви, включно з рядком із пробілів.
- Редагування назви, опису, категорії та пріоритету.
- Перемикання виконання.
- Фільтри: всі, виконані та невиконані.
- Статистика, обчислена з повного списку.
- Окремі повідомлення для порожнього списку та результату фільтра.
- Відкладене видалення на 5 секунд із кнопкою «Скасувати» та прогресом.
- Візуальне позначення завдання, яке очікує видалення.
- Toast після створення, редагування, остаточного видалення та помилок.
- Скидання до початкових завдань.
- Збереження завдань і фільтра між перезавантаженнями.
- Заголовок вкладки з кількістю невиконаних завдань.

Одночасно доступне одне відкладене видалення. Решта дій залишається доступною;
змінювати саме завдання, яке очікує видалення, не можна.
Поки видалення не підтверджене, завдання залишається у списку, статистиці
та збережених даних. Після перезавантаження незавершене видалення скасовується.

Повідомлення звичайних операцій автоматично зникають через 3,5 секунди.
Повідомлення Undo існує незалежно від них, тому інша операція не прибирає
можливість скасувати видалення.

## Організація стану

Єдиним джерелом актуального списку завдань є useReducer у TaskProvider.
Reducer підтримує типізовані дії add, toggle, update, requestDelete,
confirmDelete, undoDelete і reset. Він не створює таймерів та не звертається
до браузерних API.

TaskContext надає стан і операції компонентам. useTaskContext перевіряє,
що компонент розміщений усередині TaskProvider. Через props передаються
лише конкретне завдання картці або початкові дані форми редагування.

TaskForm зберігає локальну чернетку. При виборі іншого завдання key форми
змінюється, тому поля ініціалізуються його значеннями без Effect для
копіювання props у state. Зміни завдання потрапляють у reducer через update.

Список за фільтром і статистика обчислюються під час рендерингу.
Для них немає окремого state або Effect.

## Persistence і побічні ефекти

- Ключ завдань: study-planner.tasks.
- Ключ фільтра: study-planner.filter.
- Ініціалізатор reducer читає збережені завдання.
- Дані перевіряються за структурою, типами полів, пріоритетами та унікальністю id.
- Порожній збережений масив є коректним.
- За відсутності або пошкодження даних використовуються initialTasks.
- Effect зберігає завдання після зміни їхнього масиву.
- useLocalStorage<T> використовується для фільтра та не зберігає копію tasks.
- Помилки доступу до сховища не зупиняють застосунок.
- Окремий Effect синхронізує document.title з кількістю невиконаних.
- Effect видалення створює setTimeout і очищує його через clearTimeout.
- Progress використовує окремий інтервал із clearInterval у cleanup.
- Pending deletion, чернетка редагування та Toast не записуються в localStorage.

Undo і reset очищують pending deletion. Токен операції захищає reducer
від застарілого confirmDelete. Cleanup також виконується при unmount
та повторному запуску Effects у StrictMode.

## Перевірка в браузері

1. Відкрити застосунок, додати завдання і перевірити Toast та очищення форми.
2. Спробувати порожню назву та назву лише з пробілів.
3. Відредагувати всі чотири поля, зберегти зміни і перевірити Toast.
4. Скасувати редагування без збереження.
5. Перемкнути виконання, перевірити статистику та заголовок вкладки.
6. Вибрати фільтр, перезавантажити сторінку і перевірити його відновлення.
7. Почати видалення, перевірити позначку та прогрес, натиснути «Скасувати».
8. Повторити видалення і зачекати 5 секунд: завдання має зникнути.
9. Перезавантажити сторінку: остаточно видалене завдання не відновлюється.
10. Перезавантажити під час очікування: завдання залишається, таймер не відновлюється.
11. Скинути дані під час очікування: початкові завдання мають залишитися й після 5 секунд.
12. Видалити всі завдання, перезавантажити і перевірити збережений порожній список.
13. Перевірити окреме повідомлення порожнього фільтра.
14. Натиснути «Скинути дані» для повернення до початкового списку.

Автоматичні тести перевіряють reducer, незмінність даних, Undo,
застарілі підтвердження, скидання та обробку пошкодженого сховища.
Вони запускаються стандартним Node.js test runner без додаткових залежностей.
